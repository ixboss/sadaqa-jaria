# اختبارات E2E — شاشة الأذكار بنمط التركيز (Focus Mode)

أتمتة متصفح حيّ عبر **Chrome DevTools Protocol** — صفر تبعيات، صفر إطارات اختبار.
السكربت: [`tests/e2e-adhkar-pager.mjs`](../tests/e2e-adhkar-pager.mjs) (الاسم تاريخي — يغطي نمط التركيز الحالي).

## التشغيل

```bash
# 1) من جذر المستودع، شغّل خادماً محلياً (لا توجد خطوة بناء):
python -m http.server 8123 --bind 127.0.0.1

# 2) في نافذة أخرى:
node tests/e2e-adhkar-pager.mjs
```

المتطلبات: Node ≥ 22 (WebSocket مدمج)، ومتصفح من عائلة Chromium. السكربت يُشغّل
Edge/Chrome بوضع headless على المنفذ `9223` مع ملف شخصي مؤقت.

متغيرات البيئة الاختيارية:

| المتغير | الافتراضي | الاستخدام |
|--------|-----------|----------|
| `E2E_BASE` | `http://127.0.0.1:8123/index.html` | عنوان الصفحة |
| `E2E_CDP_PORT` | `9223` | منفذ تصحيح المتصفح |
| `E2E_BROWSER` | مسار Edge على Windows | مسار متصفح Chromium آخر |

الخروج: `0` للنجاح الكامل، `1` لأي فشل، `2` لانهيار السكربت نفسه.

## ما الذي يختبره (٨١ تأكيداً)

شاشة الأذكار اليوم **نمط تركيز**: ذكرٌ واحد ممركز بلا بطاقات، الضغط في أي مكان
يعدّ تكراراً واحداً، وعند إتمام عدّ الذكر ينتقل التالي بتلاشٍ وانزلاق.

| السيناريو | التأكيدات |
|-----------|-----------|
| **(أ) تخطيط نمط التركيز** | عنوان الرأس = اسم القسم ← البداية على «١ | ٢١» ← نص الذكر مرسوم وغير فارغ ← **لا بقايا بطاقات** (لا `.dhikr-card` ولا `.thikr-tap-btn`) ← كتلة الذكر متمركزة رأسياً في المنصة |
| **(ب) الضغط يعدّ والإتمام ينقل** | ذكر بتكرار ≥٣ ← العدّاد يصعد بدون نقل والتقدّم يُحفظ تدريجياً ← الضغطة الأخيرة **تنقل تلقائياً** للذكر التالي ← الحفظ في `localStorage["ath_…"]` = الهدف ← الضغط الزائد لا يعدّ فوق الهدف ← ذكر ١/١ ينقل بضغطة واحدة ← **حارس تحجيم الصفحة** |
| **(ج) السحب الأفقي RTL** | سحب لليسار = التالي ← سحب لليمين = السابق ← **السحب لا يعدّ تكراراً** (قيمة `ath_…` ثابتة قبل/بعد) |
| **(د) الخطوط ١٠٠٪–٢٠٠٪** | لكل درجة ١.٠ / ١.٣ / ١.٤ (الافتراضية) / ٢.٠ وعبر **كل الأذكار**: صفر تجاوز أفقي، النص غير مقصوص أفقياً، **التذييل فوق شريط التنقّل**، والنص الطويل كامل الوصول داخل منطقته |
| **(هـ) صفر تمرير عمودي** | `#content.scrollTop === 0` خلال تصفّح كل الأذكار و`overflow-y: hidden` |
| **(و) الانحدار** | كل الأقسام تُفتح على أول ذكر بعدد صحيح ← ☆ المفضلة تُحفظ عبر زر الشريط ← **قائمة الخيارات** تفتح وفلتر المفضلة يعمل ← الرجوع يهبط على شبكة الأقسام ← **صفر أخطاء كونسول** |
| **(ز) التذييل فوق الشريط عبر منافذ العرض** | لكل منفذ من ٣٢٠×٦٩٣ / ٣٩٠×٨٤٤ / ٣٩٣×٨٥٢ / ٨٤٤×٣٩٠ (أفقي) × ١.٠ / ١.٣ / ٢.٠: **الشريط ظاهر** ← **التذييل لا يختفي خلف الشريط** ← المنصة داخل منفذ العرض بلا تجاوز أفقي |
| **(ح) وضع التشغيل (Play)** | زر التشغيل يتلون بضغطه ← ينقل تلقائياً كل ~٦ ثوانٍ ← الإيقاف يمنع النقل ← مغادرة الشاشة تُوقف المؤقّت |

## ملاحظات تنفيذ صادقة (خدعات الأتمتة)

١. **النقر المُصطنَع**: `Input.dispatchTouchEvent` لا يُنتج `click` في headless —
   يستخدم السكربت `Input.emulateTouchFromMouseEvent` الذي يمرّ عبر خط اللمس الحقيقي.

٢. **السحب**: تُرسَل `TouchEvent` مُصطنَعة (`touchstart`/`touchend` بفارق إحداثيات)
   لأن نمط التركيز يقود التنقل من مستمعات اللمس نفسها؛ الأحداث الاصطناعية تصل
   إلى مستمعات الصفحة مباشرة.

٣. **`getBoundingClientRect` عبر CDP**: كائن `DOMRect` يُتسلسَل كـ `{}` فارغ —
   يُحوِّله السكربت إلى كائن عادي `{x, y, width, height}` قبل العودة (وإلا
   `undefined + … = NaN → null` في JSON فتنهار إحداثيات النقر).

٤. **أخطاء الشبكة الخارجية مستثناة**: خط الويب Amiri-Quran المُحمَّل مسبقاً يُعيد
   ٤٠٤ (خطأ خارجي سابق لهذه التغييرات)؛ التطبيق يعمل بخطوطه المدمجة.

## خطة الاختبار اليدوي

**(أ) نمط التركيز**: افتح أذكار الصباح → ذكر واحد ممركز، بلا بطاقات، أسفل الشاشة
«١ | ٢١» + «مرة واحدة» + ثلاثة أيقونات (نجمة/تشغيل/مشاركة).

**(ب) الضغط يعدّ**: اضغط في أي مكان على المنصة → العدّاد «٠ / ٣» يصعد مع نبضة
وطَفْو `+1` → عند اكتمال العدّ: احتفال خفيف ثم **انتقال سلس للذكر التالي**.
الآخر في القسم يبقى على «اكتمل ✓». في الكونسول: `ath_<التاريخ>_<قسم>_<ذكر>` = الهدف.

**(ج) السحب**: يساراً = التالي، يميناً = السابق، بلا عدّ.

**(د) وضع التشغيل**: زر ▶ → ذكر كل ٦ ثوانٍ حتى آخر القسم؛ ▶ مجدداً أو الرجوع يوقفه.

**(هـ) المفضلة والقائمة**: نجمة الشريط تُلوَّن وتُحفظ في `athkar_favs`؛ أيقونة
القائمة تفتح شريحة «☆ المفضلة» التي تعرض المفضّل فقط.
