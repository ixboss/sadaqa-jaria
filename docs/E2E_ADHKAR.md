# اختبارات E2E — شاشة الأذكار كتقاليب أفقية

أتمتة متصفح حيّ عبر **Chrome DevTools Protocol** — صفر تبعيات، صفر إطارات اختبار.
السكربت: [`tests/e2e-adhkar-pager.mjs`](../tests/e2e-adhkar-pager.mjs).

## التشغيل

```bash
# 1) من جذر المستودع، شغّل خادماً محلياً (لا توجد خطوة بناء):
python -m http.server 8123 --bind 127.0.0.1

# 2) في نافذة أخرى:
node tests/e2e-adhkar-pager.mjs
```

المتطلبات: Node ≥ 22 (WebSocket مدمج)، ومتصفح من عائلة Chromium. السكربت يُشغّل
Edge/Chrome بوضع headless على المنفذ `9223` مع ملف شخصي مؤقت.

متغيرات البيئة الاختيارية:

| المتغير | الافتراضي | الاستخدام |
|--------|-----------|----------|
| `E2E_BASE` | `http://127.0.0.1:8123/index.html` | عنوان الصفحة |
| `E2E_CDP_PORT` | `9223` | منفذ تصحيح المتصفح |
| `E2E_BROWSER` | مسار Edge على Windows | مسار متصفح Chromium آخر |

الخروج: `0` للنجاح الكامل، `1` لأي فشل، `2` لانهيار السكربت نفسه.

## ما الذي يختبره (٨٢ تأكيداً)

| السيناريو | التأكيدات |
|-----------|-----------|
| **(الإعداد) فتح القسم بنقرة حقيقية** | النقر على بطاقة القسم يُنتج `.dhikr-slide` — وإلا **يتوقف السكربت فوراً برسالة واحدة** بدل ست إخفاقات مربِكة |
| **(أ) التفاف أفقي يميناً/يساراً RTL** | البداية على الشريحة ١ ← السحب للتالي = الشريحة ٢ ← السحب للسابق = العودة للشريحة ١ ← **بطاقة واحدة فقط** مرئية في كل لحظة (قياس المستطيلات) |
| **(ب) الضغط يعدّ ويُكتمِل** | وجود ذكر بتكرار ≥٣ ← سطر العدّاد يبلغ الهدف ← الزر يعرض `✓ اكتمل` ← شريط التقدم ١٠٠٪ ← الحفظ في `localStorage["ath_…"]` ← **الضغط لم ينقّل** (نفس الشريحة + `state.currentScreen`) ← الضغط الزائد لا يعدّ فوق الهدف ← **حارس تحجيم الصفحة** (لا يتغير `innerWidth/innerHeight`) |
| **(ج) الخطوط ١٠٠٪–٢٠٠٪** | لكل درجة من ١.٠ / ١.٣ / ١.٤ / ٢.٠ وعبر **٢١ شريحة**: صفر تجاوز أفقي، النص غير مقصوص، **البطاقة لا تتجاوز منفذ العرض إطلاقاً**، **زرّ العدّ فوق شريط التنقّل**، والنص الطويل كامل الوصول داخل البطاقة |
| **(د) صفر تمرير عمودي** | `#content.scrollTop === 0` و`pager.scrollTop === 0` خلال تصفّح كل بطاقة، و`overflow-y: hidden` على كلتا الحاويتين |
| **(هـ) الانحدار** | كل الأقسام تُفتح وكل ذكر قابل للوصول ← ☆ المفضلة تُحفظ في `athkar_favs` ← الرجوع يهبط على شبكة الأقسام مع التبويب المضيء ← **صفر أخطاء كونسول** |
| **(و) زرّ العدّ فوق الشريط عبر منافذ العرض** | لكل منفذ من ٣٢٠×٦٩٣ / ٣٩٠×٨٤٤ / ٣٩٣×٨٥٢ / ٨٤٤×٣٩٠ (أفقي) × ١.٠ / ١.٣ / ٢.٠: **الشريط ظاهر** (القياس ذو معنى) ← **زرّ العدّ لا يختفي خلف الشريط** على أي شريحة ← البطاقة داخل منفذ العرض |
| **(ح) زر التقدم التلقائي بلا ازاحة** | صندوق الزر موجود منذ أول إطار (صنف `fab-hidden` لا `display:none`) ← **لا قفزة بعد الاستقرار** (قبل/بعد متطابقان) ← **العرض والموضع لا يتغيران عند التبديل** بين «تقدم تلقائي» و«إيقاف التقدم» |

قياسات منافذ العرض (٢١ شريحة لكل منفذ/درجة): `behindNav=0` و`offScreen=0` في
الـ١٢ حالة جميعها (٣٢٠×٦٩٣ و٣٩٠×٨٤٤ و٣٩٣×٨٥٢ و٨٤٤×٣٩٠ × ١.٠/١.٣/٢.٠).

**كيف تُقرأ هذه الأرقام**: عمود «شرائح بتمرير نصّي داخلي» هو السلوك المطلوَب —
حين يطول الذكر عن ارتفاع الشاشة، يتموّر **داخل منطقة النصّ في البطاقة** (لا تقعّط
الشاشة). العدد يتذبذب بعض الشيء بين التشغيلات لأن بطاقاتٍ عند الحدّ تبلغ/لا تبلغ
نقطة التمرير حسب تقريب التخطيط — لكن التأكيدات الجوهرية ثابتة: **البطاقة لا
تتجاوز منفذ العرض إطلاقاً**، و**النص كامل الوصول**، و**زرّ العدّ فوق الشريط**.

**لماذا أُضيف السيناريو (و)**: الشاشة كانت تضع `padding-bottom: 0` على `#content`
في وضع الـ Pager، فكانت آخر شريحة تمتدّ تحت شريط التنقّل الثابت ويختفي زرّ العدّ
خلفه على البطاقات الطويلة (١/٢١ بطاقة عند ٨٠٪، حتى ١٨/٢١ عند ٢٠٠٪، و٢١/٢١ في
الوضع الأفقي). الإصلاح أعاد مساحة الشريط (`--nav-clearance-safe`)، وأضاف صمّام
تمرير داخل البطاقة مع تثبيت صفّ العدّ أسفلها للشاشات القصيرة. الآن `behindNav=0`
في كل المنافذ والنسب.

## ملاحظات تنفيذ صادقة (خدعات الأتمتة)

١. **السحب اللمسي المُصطنَع لا يُمرّر** في المتصفح headless — تحقّقنا من ذلك حتى
   ضد القوائم العمودية الموجودة في التطبيق. لذا يستخدم السكربت عجلة فأرة حقيقية
   (`Input.dispatchMouseEvent` مع `deltaX`) لتشغيل نفس آلات snap الأفقي بدقة.
   على جهاز حقيقي، السحب اللمسي يعمل طبعاً.

٢. **أخطاء الشبكة الخارجية مستثناة**: خط الويب Amiri-Quran المُحمَّل مسبقاً
   (`fonts.gstatic.com/s/amiriquran/v1/...woff2`) يُعيد **٤٠٤** في كلتا الحالتين
   (المصدر المباشر و Google Fonts CSS API). هذا خطأٌ خارج التطبيق موجود قبل هذه
   التغييرات، لذا تستثنيه تأكيدات «صفر أخطاء». يستخدم التطبيق خطوط النظام
   البديلة، فلا تأثير مرئي.

٣. **تغليف اللمس (touch-action) يُحلَّل من هدف `touchstart`**: الشريحة ومنطقة
   النص يحملان `pan-x pan-y` وإلا لحظرَ `pan-y` التفاف الـ Pager الأفقي.

٤. **`scroll-behavior: smooth` يسبق القراءة**: قبل أي قياس برنامجي لـ `scrollLeft`
   يضبط السكربت `scrollBehavior='auto'`، وفي RTL تكون قيمة `scrollLeft` سالبة
   باتجاه العناصر اللاحقة.

٥. **استقرار `scrollLeft` لا يكفي بعد الضبط البرمجي**: ضبط `scrollLeft` يُطلق
   لمّة التقاء (scroll-snap) سلسة قد تستمرّ بعد استقرار القيمة، فتُقرأ بطاقة
   مجاورة بدل المستهدفة. ينتظر السكربت استقرار **الشريحة المرئية الموسَطة**
   (`waitForCard`) لا `scrollLeft` وحده.

٦. **النقر على بطاقة القسم يستهلكه غطاء المناسبات**: `#occasion-overlay` نشط
   عند الإقلاع ويغطّي الشاشة كلها، فيبتلع أي نقرة قبل إغلاقه — لذلك يُغلق
   السكربت قبل المحاكاة، وإلا يفشل الإعداد برسالة واحدة واضحة.

٧. **التقدّم التلقائي مفعّل افتراضياً** (`getAutoAdvance() !== '0'`)، أي أن
   إتمام ذكر في سيناريو (ب) **ينقل للشريحة التالية** — لذا يُعطَّل خلال (ب)
   (يُعاد في سيناريو ز)، ولاختيار ذكر في (ز) يُشترط ألا يكون مكتملأً سابقاً
   (النقر على ذكر مكتمل لا يطلق الإكمال ولا التقدّم).

٨. **حلقة الاندفاع (surge-ring) تنفخ `scrollWidth`**: حلقة الإتمام تتوسّع
   `scale(2.4)` خلال ٧٢٠ms، والمحرك يُضمّن حدود التحويل في منطقة التمرير
   القابلة للتمرير — فيُقاس تجاوز أفقي وهمي خلال الحركة. ينتظر السكربت
   ٩٠٠ms بعد أي ضغطة قبل قياس التجاوز.

## خطة الاختبار اليدوي (بديل بدون متصفح headless)

إذا تعذّر تشغيل السكربت، تُغطّى نفس السيناريوهات يدوياً على جهاز حقيقي أو في
أدوات المطوّر:

**(أ) التفاف أفقي RTL**
1. افتح التطبيق → تبويب الأذكار → افتح «أذكار الصباح».
2. تأكّد: تُرى بطاقة واحدة فقط، الشارة `١ / ٢١`.
3. اسحب لليسار → الشارة تصبح `٢ / ٢١`. اسحب لليمين → تعود `١ / ٢١`.
4. في أدوات المطوّر: `document.getElementById('thikr-list-container').scrollLeft`
   يجب أن يكون سالباً ومضاعفاً لعرض شريحة واحدة بعد كل سحب.

**(ب) الضغط يعدّ**
1. اختر ذكراً بتكرار ≥٣. اضغط على **جسم البطاقة** (وليس زرّ العدّاد).
2. بعد كل ضغطة: يزيد سطر «n من M»، يمتلئ شريط التقدم بنسبة n/M، ويطفو `+1`.
3. عند M: يتحوّل الزر إلى `✓ اكتمل` + نبضة احتفال، وتبقى **نفس الشريحة** معروضة.
4. في الكونسول: `localStorage` يحوي `ath_<التاريخ>_<قسم>_<ذكر>` = M. أعد التحميل
   → التقدّم محفوظ وحلقة القسم في الشبكة الرئيسية تعكسه.
5. اضغط مرة إضافية → لا يتجاوز العدّ M.

**(ج) الخطوط**
1. افتح نافذة حجم الخط من زرّ الرأس. جرّب ١٠٠٪ و١٤٠٪ و٢٠٠٪.
2. في كل درجة، تصفّح كل ٢١ بطاقة: لا يوجد نصّ مقصوص أو متجاوز عرض البطاقة،
   والبطاقة **لا تتعدّى ارتفاع الشاشة** — الأذكر الطويلة تتموّر داخل النصّ.
3. تأكّد بصرياً أن البطاقة متمركزة وغير ملتصقة بحواف الشاشة.

**(د) صفر تمرير عمودي**
1. في الكونسول خلال تصفّح البطاقات:
   `document.getElementById('content').scrollTop` دائماً `0`.
2. `getComputedStyle(document.getElementById('thikr-list-container')).overflowY`
   يجب أن يكون `hidden`.

**(هـ) الانحدار**
1. افتح كل قسم وتأكّد ظهور كل الأذكار بالعدد الصحيح.
2. ☆: اضغط النجمة وأعد التحميل → `localStorage["athkar_favs"]` يحوي `"ci:i"`.
3. زرّ المصدر يفتح نافذة التخريج الصحيحة.
4. زرّ الرجوع يهبط على شبكة الأقسام مع تضيء تبويب الأذكار.
5. الكونسول: صفر أخطاء (٤٠٤ خط الويب الخارجي مُتوقَّع، انظر §٢ أعلاه).

**(و) زرّ العدّ فوق الشريط**
1. في الكونسول (على بطاقة طويلة):
   ```js
   const nav = document.getElementById('nav').getBoundingClientRect();
   const btn = document.querySelector('.dhikr-slide .thikr-tap-btn').getBoundingClientRect();
   btn.bottom <= nav.top   // true دائماً
   ```
2. كرّر بعد تغيير حجم النافذة (٣٢٠/٣٩٠/٣٩٣ عرض) والوضع الأفقي، وعند ١٠٠٪ و٢٠٠٪
   من حجم الخط.
3. في الوضع الأفقي: إن طالت ثوابت البطاقة، يتموّر محتواها داخلها و**يبقى زرّ
   العدّ** فوق الشريط السفلي.

## سيناريو (ز): التقدم التلقائي (Auto-Advance)

**الهدف:** التحقق من الانتقال الأفقي التلقائي بعد إتمام الذكر عند تفعيل الميزة.

**التأكيدات:**
1. **ذكر فردي (١/١):** اضغط → اكتمال → انتظر ١٨٠٠ مللي ثانية → `scrollLeft` يتغير بمقدار ≥٢٠٠px (RTL: يصبح أكثر سلبية)
2. **ذكر متعدد (٣/٣):** اضغط ٣× → اكتمال → انتظر ١٨٠٠ مللي ثانية → التمرير إلى الشريحة التالية
3. **الشريحة الأخيرة:** اكتمال → انتظر ١٨٠٠ مللي ثانية → `scrollLeft` لا يتغير (لا تمرير خارج القائمة)
4. **الإلغاء:** إلغاء الشريحة → اكتمال → انتظر ١٨٠٠ مللي ثانية → لا يحدث تمرير

**التغطية:** الأسطر ٢٨٦٣+ (كتلة التقدم التلقائي في `tapThikr`)، استمرار الإعدادات، اتجاه التمرير RTL.

**يدوياً:**
1. افتح أذكار الصباح → فعّل شريحة `⏭ تقدم تلقائي` (يجب أن تُضاء).
2. على ذكر ١/١: اضغط → ينتهي الذكر → بعد ١.٥ ثانية ينتقل تلقائياً للتالي.
3. على ذكر ٣/٣: اضغط ٣ مرات → عند الاكتمال ينتقل تلقائياً.
4. على آخر ذكر في القسم: اكتمل → **لا ينتقل** (يبقى على نفس الشريحة).
5. ألغِ الشريحة (تُطفأ) → اكتمل ذكراً → **لا ينتقل**.
6. أعد تحميل الصفحة → افتح القسم → حالة الشريحة تُزامَن من `localStorage.adhkar_auto_advance`.
   العدّ مثبَّتاً في أسفلها** ظاهراً قابلاً للضغط.
