هذا الملف يوثّق التغييرين الرئيسيين: (١) إصلاح تجاوز النص عند تكبير الخط حتى ٢٠٠٪،

## ١. نظام الخطوط الديناميكي (Dynamic Type)

### مقياس الخط — منزلق مستمر

التحكّم السابق كان ثلاثة أزرار مسمّاة (ص/م/ك) ثم خمس درجات ثابتة — وهي نفسها
سبب ضغط الرأس. حلّ محلها **زر واحد** يفتح نافذة منبثقة بمنزلق حقيقي
(`<input type="range" min="80" max="200" step="5">`) مع ملصق نسبة بخط هندي حيّ:

| المنزلق | `--font-scale` | `--line-height` المشتق | `--mushaf-scale` |
|---------|---------------|----------------------|------------------|
| ٨٠٪     | 0.8           | 2.00                 | 0.8              |
| ١٠٠٪    | 1.0           | 2.15                 | 1.0              |
| **١٣٠٪ (افتراضي)** | 1.3 | 2.38              | 1.3              |
| ١٥٠٪    | 1.5           | 2.53                 | 1.5              |
| ٢٠٠٪    | 2.0           | 2.90                 | 2.0              |

ملاحظات:

- `--font-size = calc(var(--font-base) * var(--font-scale)` حيث
  `--font-base: 14px` — **والافتراضي ١٣٠٪ يعطي ١٤ × ١٫٣ = ١٨٫٢px**، أي نفس
  الحجم المُعايَر سابقاً عند ١٠٠٪، فلا تتغير الواجهة الافتراضية بينما القيمة
  الداخلية للمنزلق هي ١٣٠ كما هو مطلوب.
- `applyFontSize()` **متواصلة** (لا تثبيت على درجات): تقبل ٨٠…٢٠٠ أو النسب
  العشرية ٠٫٨…٢ أو أسماء قديمة، وتكتب `--font-scale` **و`--mushaf-scale`**
  معاً = `slider/100` — أي `fontSize = base × sliderValue / 100`.
- **ارتفاع السطر ينمو مع التكبير** (معادلة `2.0 + (scale − 0.8) × 0.75`) — الأسطر
  المتزاحمة عند ٢٠٠٪ تتعب العين؛ هذه المعادلة تبقي تباعد الأسطر مريحاً.
- **نص المصحف يتبع المنزلق مباشرة** لا بنسبة مهدّأة: `--mushaf-base: 34px`
  و`--mushaf-scale` = نفس النسبة. على صفحة تملأ الشاشة يُلغي التصغير التلقائي
  التكبير (انظر `docs/QURAN_LAYOUT.md`)، فالنص ينمو حيث تسمح المساحة ويثبت عند
  التشبّع — وهذا ضمان بلا تمرير.
- **كروم القارئ لا يتجاوز ١٣٥٪**: `#screen-surah-view` و`#screen-khatmah-read`
  يضعان `--font-size: calc(var(--font-base) * min(var(--font-scale), 1.35))`،
  وإلا التهمت الكرومات المكبّرة مساحة الصفحة عند ٢٠٠٪ فلا تتسع أبداً.
- **`--nav-h` تتتبع الخط**: كانت قيمة ثابتة تخمينية فتقفز كل العناصر الثابتة
  فوق الشريط بعد قياس `syncNavSafeArea()`. الآن
  `--nav-h: calc(var(--font-size) * 4.2)` فالقيمة الثابتة تتبع المنزلق، ويصبح
  القياس المتأخر تصحيحاً ضمن px لا قفزة.
- **التوافق مع الإصدارات السابق**: `state.fontSize` القديم يُترجَم مرّة واحدة عبر
  `LEGACY_FONT_SIZE` ثم يُحذف، وتُخزَّن النسبة الرقمية في `state.fontScale`.
- **لا يوجد تصغير تحت حد الوصول**: الإصلاحات كلها في الحاويات (تنمو بدل أن تقصّ)،
  ولا يوجد أي `text-size-adjust` أو حد أدوى مفتعل.

### إصلاحات التجاوز (الجذر: الكروم، ليس النص)

الفحص أثبت أن `.thikr-text` و`.dua-text` و`.mushaf-block` تلتفّ وتكبر أصلاً بشكل صحيح.
التجاوز كله في **الكروم** ذي الأبعاد الثابتة بينما الخط الافتراضي ١.٤:

| الموقع | المشكلة | الإصلاح |
|--------|---------|---------|
| `#header` | `height: var(--header-h)` ثابت → العنوان يرسم أسفله | `min-height` + `height: auto` + `padding-top: env(safe-area-inset-top)` |
| شريط تقدم القراءة | `position: fixed; top: var(--header-h)` ينفصل عند نمو الرأس | عُنصر مطلق داخل `#header` عند `bottom: 0` |
| `#ayah-bar` | أربعة أزرار `nowrap` تحتاج ~٤٠٠px | إزالة `nowrap`، السطر يلتف، الأزرار `flex: 1 1 auto; min-width: 0` |
| `.mushaf-nav-pos` | `nowrap` يدهن فوق أزرار التنقل | `min-width: 0` + `overflow: hidden; text-overflow: ellipsis` |
| `.k-wird-badge` | تجبر الحاوية على تجاوز ٩٠٪ من الشاشة | `flex-shrink: 1; min-width: 0` |
| `#nav` | `overflow: hidden` يقصّ الأيقونة+النص عند ٢٠٠٪ | `height: auto; min-height` + `--nav-h-actual` يقيسه `syncNavSafeArea()` |
| عام | أبناء flex يحملون نصاً | `overflow-wrap: break-word` + `min-width: 0` + شبكة عمود واحد تحت ٣٤٠px |

`--nav-clearance-safe` تستخدم `max(--nav-h, --nav-h-actual)` فتعكس ارتفاع الشريط
الفعلي أينما كبر. تُكتَب `--nav-h-actual` كنمط مضمَّن على `<html>` (يتغلب على أي
media query) — لا تضع قيمة لـ `--nav-gap` في media query.

## ٢. تجربة الأذكار (تقاليب أفقية — Pager)

**الشبكة الرئيسية للأقسام لم تُمسَّ إطلاقاً.** التغيير كله داخل القسم: ذكرٌ واحد
في كل مرة، والالتقاف أفقيٌ يمشي بين الأذكار (على غرار تطبيق «أمين»). لا شريط
تحكّم سفلي ولا أزرار جانبية — التحكّم بالخط عبر رأس الشاشة فقط.

### البنية

```
#content.pager-dhikr            ← overflow:hidden + مساحة شريط التنقل
  #screen-thikr-view             ← flex column, height: 100% (تُفعَّل بـ .active)
    .dhikr-filter-row            ← شريحة المفضلة (flex: 0 0 auto)
    #thikr-list-container        ← الـ Pager: scroll-snap-type: x mandatory
      .dhikr-slide × n           ← flex:none; width:100% — شريحة لكل ذكر
        .dhikr-card              ← margin:auto; max-height:100%; max-width:460px
```

- **RTL تلقائي** عبر `dir="rtl"` على `<html>`: السحب لليسار = التالي، بدون أي
  شفرة اتجاه. `scroll-snap-align: center` على كل شريحة، والشريط مخفي
  (`scrollbar-width: none`).
- تُقلَّب `.pager-dhikr` في `showScreen` وحسب، فلا تتأثر بقية الشاشات.

### البطاقة `.dhikr-card`

```
┌───────────────────────────────────┐
│ ٣ / ١٢                    ☆       │  شارة الموضع + المفضلة
│                                   │
│        النص العربي (متمركز)        │  .thikr-text — المنطقة المرنة الوحيدة
│                                   │
│                        ⧉ نسخ       │
│ ١ من ٣ مرات                        │  سطر التكرار
│ ▓▓▓▓░░░░░░░░░░░░░░░░░░ ٣٣٪          │  شريط تقدم رفيع
│ [المصدر]              [اضغط: ١/٣] │  .dhikr-bottom — صفٌ واحد، لا التفاف
└───────────────────────────────────┘
```

- **محصورةٌ بارتفاع الشريحة** (`max-height: 100%` + `margin: auto`): تتمركز
  عمودياً وأفقياً حين تتّسع، وتتقلّص حين يطول الذكر.
- **التقلّص يقع على منطقة النصّ وحدها** (`.thikr-text { flex: 0 1 auto;
  min-height: 0; overflow: hidden auto }`)، فيتموّر النصّ داخل البطاقة، فلا يحدث
  تمرير عمودي للشاشة أبداً مهما كبر الخط — ذكرٌ أطول من الشاشة يُقرأ بالتمرير
  داخل بطاقته. `padding-bottom: 8px` يستوعب حروف التشكيل المتدلّية فلا يظهر
  شريط تمرير وهمي.
- **صمّام الأمان على الشاشات القصيرة**: حين تتجاوز *ثوابت* البطاقة (الشارة + النسخ
  + سطر التكرار + شريط التقدم + زرّ العدّ) ارتفاع الشريحة — يحدث ذلك على الشاشات
  القصيرة جداً كالوضع الأفقي — لا تكفي منطقة النصّ وحدها. لذلك البطاقة نفسها
  `overflow-y: auto` وصفّ العدّاد `.dhikr-bottom { position: sticky; bottom: 0 }`
  يبقى مثبَّتاً في أسفلها: النصّ يتموّر، و**زرّ العدّ يبقى مرئياً قابلاً للضغط**.
- **`max-width: 460px`** يحافظ على سطور قصيرة قابلة للقراءة على الشاشات
  العريضة (أفقي/تابلت/سطح المكتب) بدل تمدّد السطر عبر الشاشة كلها.
- **العدّاد**: الضغط في أي مكان على البطاقة يزيد العدّ — معالج واحد مفوَّض على
  `#thikr-list-container` يتجاهل الأزرار (`button`/`.copy-btn`) ويستدعي
  `tapThikr` كما هو: تحديث سطر التكرار وعرض شريط التقدم و`aria-valuenow`، مع
  `+1` طافٍ ونبضة ومؤثر إتمام (`✓ اكتمل` + احتفال + إعلان `aria-live`).
  الضغط لا يمرّر الصفحة ولا يتنقّل (`touch-action: pan-x pan-y` على الشريحة
  والنص، والـ Pager يتجاهل السحب العمودي).

### مساحة شريط التنقل (إصلاح)

`#content.pager-dhikr` **لا** يضع `padding-bottom: 0`. البطاقة محصورةٌ بارتفاع
الشريحة، فلو امتدت الشريحة إلى أسفل الشاشة لاختبأ زرّ العدّ خلف شريط التنقّل
الثابت المعيم (`rgba(12,42,52,0.96)`) — وهو ما كان يحدث على البطاقات الطويلة
بالضبط. القيمة الآن `calc(var(--nav-clearance-safe) + 12px)`، أي نفس توكين
المسافة الذي تستخدمه بقية الشاشات (ويتضمّن `env(safe-area-inset-bottom)` و
`max(--nav-h, --nav-h-actual)`، فيكبر مع الشريط حين تكبر الخطوط).

قياسات حيّة على ٣٩٠×٨٤٤ (قسم أذكار الصباح، ٢١ بطاقة) — عدد الشرائح التي يختفي
زرّ عدّها خلف الشريط:

| نسبة الخط | ٨٠٪ | ١٠٠٪ | ١٣٠٪ | ١٥٠٪ | ٢٠٠٪ |
|-----------|-----|------|------|------|------|
| قبل الإصلاح | ١ | ١ | ٥ | ١٠ | ١٨ |
| بعد الإصلاح | ٠ | ٠ | ٠ | ٠ | ٠ |

بعد الإصلاح يبقى زرّ العدّ أعلى الشريط بـ ٧١–٨٣px في كل النسب.

### الميزتان

**المفضلة**: زر ☆ على كل بطاقة، تُحفَن في `localStorage["athkar_favs"]` كمصفوفة
مفاتيح `"catIndex:itemIndex"` — نفس نظام مفاتيح التقدم `ath_*` تماماً. شريحة لاصقة
`★ المفضلة` أعلى القسم تعرض فقط المفضّل فيه (تعيد استخدام `openCategory(ci, true)`).
لا شاشات جديدة، الشبكة الرئيسية كما هي.

**المصدر**: خريطة `ATHKAR_SOURCES` (٦٥ مدخلاً) بمفاتيح `"catIndex:itemIndex"`، كل
سلسلة فيها **منسوخة حرفياً من حصن المسلم** (`hisn_almuslim.json`) — تم التحقق
آلياً من كل سلسلة ضد مجموعة النصوص الفعلية في المصدر (`verify_verbatim`:
`verbatim: 65, NOT-VERBATIM: 0`). زر "المصدر" يفتح نافذة فيها اسم القسم وموضع الذكر
والتخريج. العناصر بلا تخريج مفصّل في المصدر تأخذ Label عام **`حصن المسلم`** —
لا اختراع أي راوٍ أو درجة حديث أبداً.

## ٣. مواصفات الحركة (Motion)

| التوكين | القيمة | الاستخدام |
|---------|-------|----------|
| `--ease-out-quart` | `cubic-bezier(0.25, 1, 0.5, 1)` | تلاشي/ظهور عام |
| `--ease-out-expo` | `cubic-bezier(0.16, 1, 0.3, 1)` | حركات خروجة طويلة |
| `--ease-in-out-quart` | `cubic-bezier(0.76, 0, 0.24, 1)` | انتقالات متوازنة |
| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | نوابض قوية (مؤشر التنقل) |
| `--ease-spring-soft` | `cubic-bezier(0.5, 1.5, 0.4, 1)` | نوابض لطيفة |
| `--ease-spring-snap` | `cubic-bezier(0.5, 1.7, 0.6, 1)` | كل تفاعلات الأزرار |
| `--motion-duration-fast` | 180ms | تفاعلات الضغط |
| `--motion-duration` | 260ms | الحركات الافتراضية |
| `--bounce-step` | 12ms | تدرّج ظهور العناصر |

مواصفات حركات الأذكار:

| العنصر | المدة | المنحنى | المُحفِّز |
|--------|------|---------|----------|
| نمو شريط التقدم | 320ms | `--ease-spring-snap` | كل ضغطة عدّاد |
| نبضة الضغط على البطاقة والأزرار | 140–180ms scale 0.94–0.99 | `--ease-spring-snap` | `:active` |
| ☆ المفضلة | 180ms scale 1.25 | `--ease-spring-snap` | الضغط |
| `+1` الطافي | حركة `Motion.floater` الموجودة | — | كل ضغطة عدّاد |
| تدرّج ظهور البطاقات | `Motion.staggerIn` الموجودة | — | فتح القسم |
| الالتقاط الأفقي بين الأذكار | `scroll-behavior: smooth` | — | السحب/عجلة الفأرة |

`prefers-reduced-motion`: التطبيق يحترمه مسبقاً (تُلغى الـ transforms فوراً في
`showScreen`، وتُعطَّل النوابض). الالتقاط الأفقي يستخدم `behavior: 'smooth'`
الذي يحترم إعداد النظام أيضاً.

## ٤. ملاحظات الوصول (Accessibility)

**النوع الديناميكي**
- خمس درجات حتى ٢٠٠٪ (الحد الذي تختبره إرشادات WCAG للتكبير).
- مبدأ الإصلاح: **الحاوية هي التي تتكيّف**. كل حاويات النص بلا ارتفاع ثابت،
  والكروم بلا عرض/ارتفاع ثابت، والأزرار `flex` تلتف. لا تصغير للنص إطلاقاً.
- في الأذكار: البطاقة محصورةٌ بارتفاع الشريحة ومنطقة النصّ هي القابلة للتمرير
  داخلياً، فأي خط — حتى ٢٠٠٪ — يبقى قابلاً للقراءة كاملاً دون قصّ ودون تموّر
  الشاشة.

**RTL والعربية**
- `dir="rtl"` على نص الذكر، و`text-align: right`، و`white-space: pre-line` يصون
  الأسطر الشعرية للأذكار متعددة الأسطر.
- الأرقام بالعربية الهندية عبر `toArabicNum` في كل المواضع المرئية.
- ترتيب القراءة: شارة الموضع أولاً ثم النص ثم العدّاد — يطابق ترتيب `aria`.
- `overflow-wrap: break-word` + `word-break: normal` (لا `word-break: break-all`
  الذي يكسر الكلمات العربية بشكل قبيح).

**قارئات الشاشة**
- `role="progressbar"` + `aria-valuenow/min/max` على شريط تقدم كل ذكر، يُحدَّث
  حيّاً مع كل ضغطة.
- `aria-pressed` على أزرار المفضلة ودرجات الخط والوضع الليلي.
- `aria-live` (عبر `AccessibilityHelper.announceMessage`) يعلن الإتمام والإضافة/
  الإزالة من المفضلة. منطقة الإعلان مخفية بنمط `sr-only` القياسي (clip) وليس
  بالإزاحة إلى `−9999px` — الإزاحة كانت تُفعّل «shrink-to-fit» على الجوال
  فتكبّر الصفحة كلها بعد كل ذكر (راجع `docs/E2E_ADHKAR.md`).
- **الالتقاف `x mandatory`**: الحبس العمودي الذي يخشى منه مع `mandatory` لا
  يحدث هنا لأن التمرير العمودي يعيش داخل منطقة نصّ البطاقة، لا في حاوية الـ snap.

**التباين اللوني**
- الوضع الداكن: `--text: #f3f0e7` على `--bg: #0a1f28` (تباين عالٍ)؛
  `--text-dim: #9fb8b6` للنص الثانوي.
- الوضع الفاتح ينعكس بالكامل، والأشرطة الثابتة تأخذ لون كريمي شفافاً مع blur.

## ٥. اختبارات E2E

`tests/e2e-adhkar-pager.mjs` — أتمتة حيّة عبر Chrome DevTools Protocol (Node ≥ 22
فقط، صفر تبعيات) ضد `python -m http.server 8123`. التفاصيل الكاملة، الأوامر،
ونتائج آخر تشغيل في [`docs/E2E_ADHKAR.md`](E2E_ADHKAR.md). تغطّي:

١. **الالتقاف RTL**: السحب لليسار ينتقل للتالي ولليسار للسابق، بطاقة واحدة
   مرئية في كل مرة، الشارة تطابق الشريحة الظاهرة.
٢. **العدّ بالضغط في أي مكان**: يزيد العدّاد ويُكمّل ويحفظ في `ath_*`، ولا يتنقّل
   أو يمرّر، ولا يتجاوز الهدف، ولا يُكبِر الصفحة (shrink-to-fit).
٣. **مصفوفة الخطوط** ١.٠ / ١.٣ / ١.٤ / ٢.٠: لا تجاوز أفقي، لا قصّ، البطاقة لا
   تتجاوز منفذ العرض، النصّ الطويل قابل للوصول كاملاً داخل البطاقة، **زرّ العدّ
   يبقى فوق شريط التنقّل**.
٤. **لا تمرير عمودي** للشاشة في كل الشرائح.
٥. **انحدار النظم**: كل قسم يُفتح وكل ذكر يصل، ☆ المفضلة تستمر، الرجوع يهبط على
   الشبكة الرئيسية، صفر أخطاء في الكونسول.
٦. **زرّ العدّ فوق الشريط عبر منافذ العرض** ٣٢٠×٦٩٣ و٣٩٠×٨٤٤ و٣٩٣×٨٥٢
   و٨٤٤×٣٩٠ (أفقي) × ١.٠ / ١.٣ / ٢.٠.

## ٦. التقدم التلقائي (Auto-Advance)

**الميزة:** عند التفعيل، يُنقل المستخدم تلقائياً إلى الذكر التالي بعد إتمام الذكر الحالي (الوصول إلى الهدف: ١/١، ٣/٣، ١٠٠/١٠٠، إلخ) بتأخير ١.٥ ثانية.

**الواجهة:**
- زرّ عائم `.dhikr-auto-fab` (position: fixed) أسفل الشاشة، يظهر فقط داخل قسم
  أذكار. يحمل التسمية «تقدم تلقائي» / «إيقاف التقدم».
- شريحة تبديل في `.dhikr-filter-row` (السطر ١١٠١)، بجانب شريحة المفضلة.
- الشريحة تُضيء (`.active`) عند التفعيل، وتُطفأ عند الإلغاء.

**إزالة ازاحة التخطيط عند الفتح (المهم):**
كان للزر قفزتان ظاهرتان عند فتح القسم:
1. `display: none → flex` يُظهر الزر فوراً دون أي انتقال (الـ CSS لا يستطيع
   تحريك `display`)، فيقفز عند أول رسم للشاشة.
2. `bottom: calc(var(--nav-clearance-safe) + 16px)` حيث تُكتَب
   `--nav-clearance-safe` *لاحقاً* بقياس `syncNavSafeArea()` — فالزر (وأي عنصر
   ثابت فوق الشريط) يتحرك عمودياً بعد أول إطار، ويتكرر ذلك عند كل تغيير للخط.

الإصلاح من جذوره — **صندوق الزر محسوب منذ أول إطار**:

- الزر دائماً في DOM ويُخفى بالصنف `.fab-hidden`
  (`opacity: 0; visibility: hidden; transform: translateY(14px); pointer-events: none`)
  بدل `display: none`، فصندوقه النهائي موجود قبل ظهوره، والدخول نقلٌ وشفافية
  فقط على الـ GPU (٢٠٠ms). `visibility` متأخّرة ٢٠٠ms عند الإخفاء فقط حتى لا
  تُبتلع الحركة.
- `--nav-h` صارت `calc(var(--font-size) * 4.2)` فتتبع حجم الخط — القيمة
   الثابتة قريبة جداً من النهائية، ويصبح القياس المتأخر تصحيحاً ضمن px.
- `min-width` للقسم `calc(var(--font-size) * 3.4)` + `white-space: nowrap`،
  فتبديل النص بين «تقدم تلقائي» و«إيقاف التقدم» لا يغيّر عرض الصندوق أبداً.

**النتيجة:** صندوق الزر متطابق قبل/بعد الاستقرار وبعد التبديل (قياسات
`tests/e2e-adhkar-pager.mjs` قسم ح).

**الإعدادات:**
- `Settings.getAutoAdvance()` / `setAutoAdvance(v)` — تستخدم `localStorage.adhkar_auto_advance` (القيمة `'1'` أو غائبة).
- مُزامَنة في `openCategory()` عند فتح أي قسم، بحيث تعكس الشريحة الحالة المحفوظة.

**المنطق (index.html:2863+):**
بعد اكتمال الذكر في `tapThikr()`:
1. التحقق من `Settings.getAutoAdvance()`
2. إيجاد رقم الشريحة الحالية والعدد الإجمالي
3. إذا لم تكن آخر شريحة: `setTimeout(() => { container.scrollBy({ left: -slideWidth, behavior: 'smooth' }) }, 1500)`
4. RTL: `scrollLeft` السالب يعني التقدم نحو اليسار الفعلي (التالي)

**الحماية:**
- الشريحة الأخيرة **لا تتقدم** — يبقى المستخدم على الذكر المكتمل.
- عند إلغاء الميزة، لا يحدث أي تمرير.

**الاختبارات:** سيناريو (g) في `tests/e2e-adhkar-pager.mjs` يغطّي أربعة اختبارات: ذكر فردي (١/١)، ذكر متعدد (٣/٣)، الشريحة الأخيرة لا تتقدم، الإلغاء لا يمرّر.
