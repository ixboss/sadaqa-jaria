# اختبارات E2E — شاشة الأذكار كتقاليب أفقية

أتمتة متصفح حيّ عبر **Chrome DevTools Protocol** — صفر تبعيات، صفر إطارات اختبار.
السكربت: [`tests/e2e-adhkar-pager.mjs`](../tests/e2e-adhkar-pager.mjs).

## التشغيل

```bash
# 1) من جذر المستودع، شغّل خادماً محلياً (لا توجد خطوة بناء):
python -m http.server 8123 --bind 127.0.0.1

# 2) في نافذة أخرى:
node tests/e2e-adhkar-pager.mjs
```

المتطلبات: Node ≥ 22 (WebSocket مدمج)، ومتصفح من عائلة Chromium. السكربت يُشغّل
Edge/Chrome بوضع headless على المنفذ `9223` مع ملف شخصي مؤقت.

متغيرات البيئة الاختيارية:

| المتغير | الافتراضي | الاستخدام |
|--------|-----------|----------|
| `E2E_BASE` | `http://127.0.0.1:8123/index.html` | عنوان الصفحة |
| `E2E_CDP_PORT` | `9223` | منفذ تصحيح المتصفح |
| `E2E_BROWSER` | مسار Edge على Windows | مسار متصفح Chromium آخر |

الخروج: `0` للنجاح الكامل، `1` لأي فشل، `2` لانهيار السكربت نفسه.

## ما الذي يختبره (٣٥ تأكيداً)

| السيناريو | التأكيدات |
|-----------|-----------|
| **(أ) التفاف أفقي يميناً/يساراً RTL** | البداية على الشريحة ١ ← السحب للتالي = الشريحة ٢ ← السحب للسابق = العودة للشريحة ١ ← **بطاقة واحدة فقط** مرئية في كل لحظة (قياس المستطيلات) |
| **(ب) الضغط يعدّ ويُكتمِل** | وجود ذكر بتكرار ≥٣ ← سطر العدّاد يبلغ الهدف ← الزر يعرض `✓ اكتمل` ← شريط التقدم ١٠٠٪ ← الحفظ في `localStorage["ath_…"]` ← **الضغط لم ينقّل** (نفس الشريحة + `state.currentScreen`) ← الضغط الزائد لا يعدّ فوق الهدف ← **حارس تحجيم الصفحة** (لا يتغير `innerWidth/innerHeight`) |
| **(ج) الخطوط ١٠٠٪–٢٠٠٪** | لكل درجة من ١.٠ / ١.٣ / ١.٤ (الافتراضية) / ٢.٠ وعبر **٢١ شريحة**: صفر تجاوز أفقي، النص غير مقصوص، **البطاقة لا تتجاوز منفذ العرض إطلاقاً**، والنص الطويل كامل الوصول داخل البطاقة |
| **(د) صفر تمرير عمودي** | `#content.scrollTop === 0` و`pager.scrollTop === 0` خلال تصفّح كل بطاقة، و`overflow-y: hidden` على كلتا الحاويتين |
| **(هـ) الانحدار** | كل الأقسام تُفتح وكل ذكر قابل للوصول ← ☆ المفضلة تُحفظ في `athkar_favs` ← الرجوع يهبط على شبكة الأقسام مع التبويب المضيء ← **صفر أخطاء كونسول** |

## النتائج (آخر تشغيل)

```
35/35 passed
```

قياسات مصفوفة الخطوط (٢١ شريحة لكل درجة):

| الدرجة | تجاوز أفقي | نص مقصوص | شرائح بتمرير نصّي داخلي | نص غير قابل للوصول | البطاقة تتجاوز الشاشة |
|--------|-----------|----------|------------------------|--------------------|--------------------|
| ١٠٠٪   | 0 | 0 | 1 | 0 | 0 |
| ١٣٠٪   | 0 | 0 | 4 | 0 | 0 |
| ١٤٠٪ (الافتراضية) | 0 | 0 | 4 | 0 | 0 |
| ٢٠٠٪   | 0 | 0 | 13–21 | 0 | 0 |

**كيف تُقرأ هذه الأرقام**: عمود «شرائح بتمرير نصّي داخلي» هو السلوك المطلوَب —
حين يطول الذكر عن ارتفاع الشاشة، يتموّر **داخل منطقة النصّ في البطاقة** (لا تقعّط
الشاشة). العدد عند ٢٠٠٪ يتذبذب بين ١٣ و٢١ بين التشغيلات لأن بطاقاتٍ عند الحدّ
تبلغ/لا تبلغ نقطة التمرير حسب تقريب التخطيط — لكن التأكدين الجوهريين ثابتان:
**البطاقة لا تتجاوز منفذ العرض إطلاقاً**، و**النص كامل الوصول**.

## ملاحظات تنفيذ صادقة (خدعات الأتمتة)

١. **السحب اللمسي المُصطنَع لا يُمرّر** في المتصفح headless — تحقّقنا من ذلك حتى
   ضد القوائم العمودية الموجودة في التطبيق. لذا يستخدم السكربت عجلة فأرة حقيقية
   (`Input.dispatchMouseEvent` مع `deltaX`) لتشغيل نفس آلات snap الأفقي بدقة.
   على جهاز حقيقي، السحب اللمسي يعمل طبعاً.

٢. **أخطاء الشبكة الخارجية مستثناة**: خط الويب Amiri-Quran المُحمَّل مسبقاً
   (`fonts.gstatic.com/s/amiriquran/v1/...woff2`) يُعيد **٤٠٤** في كلتا الحالتين
   (المصدر المباشر و Google Fonts CSS API). هذا خطأٌ خارج التطبيق موجود قبل هذه
   التغييرات، لذا تستثنيه تأكيدات «صفر أخطاء». يستخدم التطبيق خطوط النظام
   البديلة، فلا تأثير مرئي.

٣. **تغليف اللمس (touch-action) يُحلَّل من هدف `touchstart`**: الشريحة ومنطقة
   النص يحملان `pan-x pan-y` وإلا لحظرَ `pan-y` التفاف الـ Pager الأفقي.

٤. **`scroll-behavior: smooth` يسبق القراءة**: قبل أي قياس برنامجي لـ `scrollLeft`
   يضبط السكربت `scrollBehavior='auto'`، وفي RTL تكون قيمة `scrollLeft` سالبة
   باتجاه العناصر اللاحقة.

## خطة الاختبار اليدوي (بديل بدون متصفح headless)

إذا تعذّر تشغيل السكربت، تُغطّى نفس السيناريوهات يدوياً على جهاز حقيقي أو في
أدوات المطوّر:

**(أ) التفاف أفقي RTL**
1. افتح التطبيق → تبويب الأذكار → افتح «أذكار الصباح».
2. تأكّد: تُرى بطاقة واحدة فقط، الشارة `١ / ٢١`.
3. اسحب لليسار → الشارة تصبح `٢ / ٢١`. اسحب لليمين → تعود `١ / ٢١`.
4. في أدوات المطوّر: `document.getElementById('thikr-list-container').scrollLeft`
   يجب أن يكون سالباً ومضاعفاً لعرض شريحة واحدة بعد كل سحب.

**(ب) الضغط يعدّ**
1. اختر ذكراً بتكرار ≥٣. اضغط على **جسم البطاقة** (وليس زرّ العدّاد).
2. بعد كل ضغطة: يزيد سطر «n من M»، يمتلئ شريط التقدم بنسبة n/M، ويطفو `+1`.
3. عند M: يتحوّل الزر إلى `✓ اكتمل` + نبضة احتفال، وتبقى **نفس الشريحة** معروضة.
4. في الكونسول: `localStorage` يحوي `ath_<التاريخ>_<قسم>_<ذكر>` = M. أعد التحميل
   → التقدّم محفوظ وحلقة القسم في الشبكة الرئيسية تعكسه.
5. اضغط مرة إضافية → لا يتجاوز العدّ M.

**(ج) الخطوط**
1. افتح نافذة حجم الخط من زرّ الرأس. جرّب ١٠٠٪ و١٤٠٪ و٢٠٠٪.
2. في كل درجة، تصفّح كل ٢١ بطاقة: لا يوجد نصّ مقصوص أو متجاوز عرض البطاقة،
   والبطاقة **لا تتعدّى ارتفاع الشاشة** — الأذكر الطويلة تتموّر داخل النصّ.
3. تأكّد بصرياً أن البطاقة متمركزة وغير ملتصقة بحواف الشاشة.

**(د) صفر تمرير عمودي**
1. في الكونسول خلال تصفّح البطاقات:
   `document.getElementById('content').scrollTop` دائماً `0`.
2. `getComputedStyle(document.getElementById('thikr-list-container')).overflowY`
   يجب أن يكون `hidden`.

**(هـ) الانحدار**
1. افتح كل قسم وتأكّد ظهور كل الأذكار بالعدد الصحيح.
2. ☆: اضغط النجمة وأعد التحميل → `localStorage["athkar_favs"]` يحوي `"ci:i"`.
3. زرّ المصدر يفتح نافذة التخريج الصحيحة.
4. زرّ الرجوع يهبط على شبكة الأقسام مع تضيء تبويب الأذكار.
5. الكونسول: صفر أخطاء (٤٠٤ خط الويب الخارجي مُتوقَّع، انظر §٢ أعلاه).
